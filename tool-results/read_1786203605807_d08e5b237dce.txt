    13→    13→Work Log:
    14→    14→- Inspected the existing Next.js 16 + TypeScript + Tailwind + shadcn/ui +
    15→    15→  Prisma(SQLite) scaffold. Confirmed Docker is NOT available in the sandbox.
    16→    16→- Designed a pluggable `DockerAdapter` interface with a high-fidelity
    17→    17→  `MockDockerAdapter` that persists volumes to disk (`.ossmp-data/`) and
    18→    18→  simulates container lifecycle + an in-process "deployed app" data plane.
    19→    19→  A `DockerEngineAdapter` stub keeps the same interface for real Docker.
    20→    20→- Prisma schema: `User` (with `passwordHash`), `App`, `Deployment` with FKs,
    21→    21→  indexes, unique `subdomain`. Pushed to SQLite via `bun run db:push`.
    22→    22→- Auth: dependency-free — scrypt password hashing + HMAC-signed session cookie
    23→    23→  (Node `crypto`). API: `POST /api/auth/{register,login,logout}`, `GET /api/auth/me`.
    24→    24→  Identity is always derived server-side from the session, never the client.
    25→    25→- Config: env-driven resource limits (`DEPLOY_CPU_LIMIT=0.5`,
    26→    26→  `DEPLOY_MEMORY_LIMIT_MB=512`, `DEPLOY_BASE_DOMAIN`, `DOCKER_ADAPTER=mock`).
    27→    27→- Deployment manager (`src/lib/deployments.ts`): the controlled privileged
    28→    28→  subsystem. `createDeployment` validates the app, generates unique
    29→    29→  container/volume/subdomain names, creates volume → container → starts it,
    30→    30→  enforces resource limits, syncs status to the DB. Only catalog apps can be
    31→    31→  deployed (no arbitrary images).
    32→    32→- APIs: `GET/POST /api/deployments`, `GET/DELETE /api/deployments/[id]`,
    33→    33→  `POST /api/deployments/[id]/{start,stop,restart}`, `GET .../logs`,
    34→    34→  `GET/POST .../volume`. Public deployed-app data plane:
    35→    35→  `/api/preview/[subdomain]/volume` (keyed by subdomain, only works while the
    36→    36→  container is running). `GET/POST /api/seed` + `GET /api/apps` + `/api/apps/[slug]`.
    37→    37→- Deployed-app simulation: `/preview/[subdomain]` renders a per-app simulator
    38→    38→  (counter / static-welcome / notes) that reads/writes the deployment's
    39→    39→  dedicated volume via the public volume API. The shell surfaces the container
    40→    40→  name, volume name, and resource limits to prove isolation to the user.
    41→    41→- Frontend: single-route SPA on `/` (per sandbox rule "only the / route") with
    42→    42→  hash-based view routing: `#/login`, `#/marketplace`, `#/apps/:slug`,
    43→    43→  `#/dashboard`, `#/deployments/:id`. Emerald/teal brand identity, dark mode
    44→    44→  via next-themes, sticky footer (`min-h-screen flex flex-col` + `mt-auto`),
    45→    45→  responsive, shadcn/ui components throughout.
    46→    46→- Seeded 3 apps: Demo Counter (persistence demo), Static Welcome (nginx:alpine),
    47→    47→  Gitea Lite (notes). Seeded via `POST /api/seed`.
    48→    48→

    53→    53→- Persistence: counter incremented to 3, deployment STOPPED (preview then
